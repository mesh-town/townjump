# CLI `holesail` 2.4.4: flags, checks, outputs, exit codes

Sources: `holesail/src/bin/holesail.mjs` (module top level), `holesail/src/lib/validateInput.js:validateInput`, `holesail/src/lib/help.js:printHelp`, `holesail/src/lib/stdout.js:stdout`, `holesail/src/index.js:Holesail.lookup`, `holesail-logger/index.js:HolesailLogger.log`, `minimist/index.js`. All outputs and codes below were captured from real runs ([cli-matrix.md](cli-matrix.md), case ids in parentheses).

## 1. argv parsing

`minimist(process.argv.slice(2))` WITHOUT options (no aliases, no types). The Rust parser must match minimist 1.2.8; the 149 reference vectors are in `testvectors/holesail-cli/minimist-vectors.json` (generated by `minimist-vectors.mjs`). Rules that matter for the CLI:

- `--k v`, `--k=v`: the value is the next token if it does not look like a flag (`-x`, `--x`); the token `-` is a value. `--k` without a value (or before a flag) is `true`. `--k=` is an empty string. `--no-k` is `k = false`. `--no-k=1` is a key named `no-k`.
- A repeat `--k a --k b` gives the array `[a, b]`.
- Short flags: `-abc` — `a`, `b`, `c` are truthy; `-p80` — `p = 80`; `-abc x` — `c = "x"`; `-h live` — `h = "live"`.
- `--` ends parsing: the rest goes to positionals (`_`). Positionals are in the `_` array.
- A value matching `^0x[0-9a-f]+$` (case-insensitive) or `^[-+]?(\d+(\.\d*)?|\.\d+)(e[-+]?\d+)?$` turns into a number (quirk 5): `03000`→3000, `0x10`→16, `1e3`→1000, `3000.5`, `.5`, `5.`→5, `+5`→5, `1e400`→Infinity. Not numbers: `" 5"`, `"5 "`, `Infinity`, `NaN`, `0b11`, `1_000`, `-5` (that is the flag `-5`).
- `--live -5` gives `live = true` and a separate flag `5 = true`.
- Dotted names nest: `--x.y=1` → `{x:{y:1}}`. `--__proto__.p=1` is ignored. Any of the 12 `Object.prototype` names (`constructor`, `__defineGetter__`, `__defineSetter__`, `hasOwnProperty`, `__lookupGetter__`, `__lookupSetter__`, `isPrototypeOf`, `propertyIsEnumerable`, `toString`, `valueOf`, `__proto__`, `toLocaleString`) in any of the three flag forms (`--name x`, `--no-name`, `--name=1`) throws `TypeError: (aliases[key] || []).forEach is not a function` (code 1); 36 vectors in total, observed on minimist 1.2.8.
- Names are case-sensitive: `--Live 3000` is a different key (it will not work).

## 2. Flags

Each flag is checked only by the branches listed; unknown flags are silently ignored.

| Flag | Value | Read by | Effect |
|---|---|---|---|
| `--help [topic]`, `-h` | topic `live`, `connect`, `filemanager` | dispatcher | help text, code 0. Any other topic (including a number) and `-h live` give the general help (in `-h live` the topic lies in `h`, while `printHelp` receives `argv.help`) |
| `--version` | — | dispatcher | prints `2.4.4` and `\n`, code 0. `-v` is NOT handled (quirk 3) |
| `--live <port>` | number | server | server mode; the value is the target local port (and the port in the DHT record). `0` is falsy, the branch is skipped |
| `--connect <key>`, positional `_[0]` | string | client | client mode; if both are given, a validation error (code 2), positionals after the first are ignored |
| `--filemanager <path>` | path | filemanager | HTTP filemanager + holesail server (see [filemanager.md](filemanager.md)) |
| `--lookup <key>` | string | lookup | prints the DHT record and exits |
| `--host <address>` | string | server, client, filemanager | server: the TARGET address (where to forward), default `127.0.0.1`; client: the address to listen on, default — from the DHT record, otherwise `127.0.0.1`. Without a value it becomes `true` and is not checked |
| `--port <port>` | number | client, filemanager | client: the port to listen on (default — from the record, otherwise 8989); filemanager: the HTTP server port and the holesail target port, default 5409; ignored with `--live` (quirk 7) |
| `--udp` | flag | server, client | UDP instead of TCP. The value `--udp=false` is the string `'false'`, truthy (quirk 6); the value goes into the DHT record as is. Filemanager: error |
| `--public` | flag | server, filemanager, client | server and filemanager: `secure = !public` (public mode); CLIENT: `secure = public` — inverted (quirk 1). See [connection-string.md](connection-string.md) |
| `--key <string>` | string | server, filemanager | a user-supplied secret / seed (≥32 characters without `--force`) |
| `--force` | flag | validation | removes the minimum-length check of `--key` |
| `--log [level]` | 0..3 | all modes | enables the log; see section 7 |
| `--username`, `--password`, `--role` | string | filemanager | filemanager parameters: the name and password both default to `admin`; the role is `admin` or `user` |
| `--safe-mode` | flag | filemanager | a port extension (not in JS): a hardened mode of the file server, see [filemanager.md](filemanager.md), "Safe mode"; `--no-safe-mode` turns it off |
| `--save-nodes <file>` | path | server, client, filemanager, lookup | a port extension (not in JS): keeps the DHT routing table in a file between runs, see section 10. Without a path: stderr `--save-nodes needs a file path`, code 1 |
| `--save-nodes-ttl <hours>` | positive number | with `--save-nodes` | a port extension (not in JS): age after which the file is ignored, default 168. Otherwise stderr `--save-nodes-ttl needs a positive number of hours`, code 1 |
| `--save-nodes-every <seconds>` | positive number | with `--save-nodes` | a port extension (not in JS): interval between writes, default 300. Otherwise stderr `--save-nodes-every needs a positive number of seconds`, code 1 |

## 3. Order of the `validateInput(argv)` checks (before help and version; each prints to stdout)

Red is `\e[31m`…`\e[0m`, yellow is `\e[33m`…`\e[0m`. Texts verbatim (without color):

1. `--key` is present and boolean (no value): `Error: Key can not be empty`, exit **0** (quirk 4).
2. `--udp` is truthy and `--host` equals `localhost` or `0.0.0.0`: yellow `Warning: localhost or 0.0.0.0 may not work properly within netcat with UDP.` — work continues.
3. `--key` is present, `key.length < 32` and no `--force`: `Error: A key should have a minimum length of 32 chars for security purposes. If you still wish to proceed use --force`, exit **2**. A number has no `length` — the comparison is false, the check is bypassed (quirk 5).
4. `--connect` is truthy and `_[0]` exists: `Error: Are you trying to use two connection strings at once? Get some holesail --help`, exit 2.
5. `--live` is truthy and its type is not a number (`--live` without a value, `abc`, `-5`, a repeat → array): `Error: Given port is not a valid number. Run holesail --help to see examples`, exit 2.
6. `--port` is truthy and not a number — the same message, 2; otherwise `--port` equals an empty string (`--port=`) — the same message, 2. `--port` without a value (`true`) — the same message, 2. `--port 0` (a number, falsy) passes.
7. `--filemanager` and `--udp`: `Error: You can't run filemanager in UDP mode.`, 2.
8. `--live` and `--filemanager`: `Error: You can't start holesail server and filemanager at the same time. If you are trying to use filemanager on a specific local port use --port instead or see holesail --help`, 2.
9. `--filemanager` and (`--connect` or `_[0]`): `Error: You tried to create a connection and start filemanager both at once. Start them separately and check your command for mistakes. See holesail --help`, 2.
10. `--filemanager` is not boolean and the path does not exist (`fs.existsSync`): `Error: Given path does not exist`, 2.
11. `--role` is set and is not `admin`/`user`: `Error: Incorrect role set. Role can be either "admin" or "user" `, 2. The message ends with a space.

The checks run before `--help`/`--version`, so `--live abc --help` prints the error and exits with 2 (`help-after-invalid`). The messages go to stdout, not stderr.

## 4. Dispatcher (after the checks)

Strictly in order, the first branch that fires ends the selection:

1. `argv.help || argv.h` → `printHelp(argv.help)`, exit 0.
2. `argv.version` → `2.4.4`, exit 0.
3. `argv.live` → server mode ([server.md](server.md)).
4. `argv.connect || argv._[0]` → client mode ([client.md](client.md)).
5. `argv.filemanager` → filemanager.
6. `argv.lookup` → lookup (section 8), exit 0.
7. otherwise → the general help, exit 0 (including `holesail` without arguments, `--foo`, `-v`, `--live 0`).

`argv.live` is parsed as a number: `--live 3000.5` gives port 3000.5 in the record and the banner, `--live 99999` is accepted (quirk 13).

**The `--filemanager` branch.** Implemented in `crates/townjump/src/cli/run/filemanager.rs`. Options: `--filemanager <path>`, `--role`, `--username`, `--password`, `--safe-mode`, `--host`, `--port`, `--public`, `--key`, `--log`. The order is as in `holesail.mjs:79–122`: the file server (`new`, `ready`) → the holesail facade (`server: true`, `port` = `argv.port || 5409`, `host` = `argv.host || '127.0.0.1'`, `udp` unset) → the `Holesail Filemanager Started` banner with a `Username/Password/Role` line and no QR → waiting: whichever comes first — `Fatal` (a message to stderr, code 1, without closing the facade) or the signal SIGINT/SIGTERM (`holesail.close()`, then closing the file server, code 130). This is the only branch where the CLI itself intercepts a signal. No path, not a string, or it does not exist → stderr `Error: INCORRECT OR NO PATH SPECIFIED`, code 1, no banner. Deviations from JS — [filemanager.md](filemanager.md), "Port deviations". `main.rs` calls `PeeroxideFactory::from_env()` before parsing argv, and this is safe: the call reads `TOWNJUMP_BOOTSTRAP`, splits on `,`, also reads `TOWNJUMP_DHT_ADAPTIVE` (`0`/`false`/`off`/`no`, any case, turn it off; unset or anything else leaves it on) and does not touch the network; `--version` prints 2.4.4 without the network — a lazy factory is not needed.

Holesail CLI - Instantly share and connect to servers

Commands:

## 6. Banner (`stdout.js:stdout`) — printed after `ready()`

The call: `stdout(protocol, type, secure, host, port, url[, filemanager])`. Printing is `console.log(frame)`, then for a server (`type == 'server'`) the QR. The client banner and the filemanager banner contain no QR. Colors do not depend on the TTY: ANSI is always written.

The text lines inside the frame, top to bottom:

1. `Holesail <PROTO> <Type> Started` — the title; `PROTO` is `TCP`/`UDP` in upper case, `Type` is `Server`/`Client`; for the filemanager — `Holesail Filemanager Started`. The title is wrapped in `cyan(underline(bold(…)))`; after it, OUTSIDE the wrapper, comes ` ⛵️` (U+26F5 U+FE0F after a space).
2. `Connection Mode: ` (magenta) + `Private Connection String` (green) or `Public Connection String` (yellow).
3. Server/filemanager: `Holesail is now listening on ` (magenta) + `<host>:<port>`. Client: `Access application on http://<host>:<port>/` (all magenta).
4. Filemanager only: ` Username: <u> Password: <p> Role: <r> ` (spaces at the edges, a separate line).
5. Server: `Connect with key: ` + dim(`<url>`); client and filemanager: `Connected to key: ` + dim(`<url>`) (the filemanager is also "Connected", not "Connect with").
6. Private: dim(`   NOTE: TREAT PRIVATE CONNECTION STRINGS HOW YOU WOULD TREAT SSH KEY, DO NOT SHARE IT WITH ANYONE YOU DO NOT TRUST    `) (3 spaces at the start, 4 at the end). Public: dim(`   NOTICE: TREAT PUBLIC STRING LIKE YOU WOULD TREAT A DOMAIN NAME ON PUBLIC SERVER, IF THERE IS ANYTHING PRIVATE ON IT, IT IS YOUR RESPONSIBILITY TO PASSWORD PROTECT IT OR USE PRIVATE MODE   `) + `\n`.

`<host>:<port>` are values from `info`: for the server `--host` (or `127.0.0.1`) and `argv.live`; for the client, the final listen address; numbers are printed by JS (`0x10` → `16`, `3000.5`). `<url>` — see [connection-string.md](connection-string.md).

The frame (`cli-box` 6.0.10, the call `cli-box('100x10', { text, autoEOL: true, vAlign: 'middle', hAlign: 'middle', stretch: true })`):

- Inner width `W = max(98, width of the longest text line without ANSI)`; full width `W + 2`. The private banner has inner width 119 (full 121), the public one 188 (190), because the NOTE/NOTICE line is long and sets the width; an unusually long key can make the key line the longest.
- Height: 10 inner lines; if there are more than 10 text lines, the height equals the number of lines. The text is vertically centered: `floor((10 − n) / 2)` empty lines on top; n = 5 (server/client): 2 on top, 3 below; n = 6 (filemanager): 2 and 2.
- Each text line is horizontally centered: `floor((W − length) / 2)` spaces on the left, the remainder on the right. The length is the visible one, without ANSI.
- The frame: top `┌` + `─`×W + `┐`, bottom `└` + `─`×W + `┘`; lines inside start with ASCII `|` (U+007C) and end with `│` (U+2502) — an asymmetry of the drawing library. In the first empty line a stray `\e[0m` sits before `│`. The exact bytes are in the JSON.
- After the frame, for the server, `qrcode-terminal` 0.12.0: `qrcode.generate(url, { small: true })`, error correction L, "half-blocks" mode (`▀`, `▄`, `█`, space), the top and bottom borders are whole lines of blocks; `console.log(<QR with its own \n at the end>)` is printed, i.e. with an empty line after. The QR encodes exactly `<url>` (for private — `hs://s000<K>`, i.e. the secret).

Print moment (quirk 8): the banner is printed right after `await conn.ready()`. The client `ready` completes as soon as `handleTCP`/`handleUDP` is called (without waiting for `listen`), so the banner comes BEFORE the local port is bound: with a busy port, first the banner, then an unhandled `EADDRINUSE`, code 1 (`conn-port-inuse`). The server `ready` waits for `await put` (the DHT write), not for `listen`. `--log` logs go to stdout BEFORE the banner (on the server the `Server listening on key` line may come before or after the banner — it depends on the network; do not check the order in tests).

**Implementation.** The QR code is a port of `qrcode-terminal` 0.12.0 (`crates/townjump/src/cli/qr/`), not the `qrcode` crate: qrcode-terminal has its own penalty function for mask selection and a byte mode with the length in UTF-16 units (each written by its low 8 bits), so the crate does not match the golden files. The frame is a port of `cli-box` 6.0.10. The banner and the frame count width in `char`, JS in UTF-16 units: they differ only on characters outside the BMP in the host/port, which is unreachable.

## 7. `--log` and the log line format

Parsing in `holesail.mjs`: `argv.log` unset → the log is off. `true` (a flag without a value) → level 1. A string → `parseInt(s, 10)`, `NaN` → 1, otherwise clamp to 0..3. A number → clamp to 0..3 (a fractional `2.5` stays fractional). `false` (`--no-log`) — the log is off (there is no branch, it stays `false`).

Levels: 0 DEBUG, 1 INFO, 2 WARN, 3 ERROR; entries with `type >= level` are printed (a numeric comparison: at level 2.5 only ERROR is visible). The line: `<ISO-time> [Holesail] [<LEVEL>] <message>`, where the time is `toISOString()` in `\e[90m`, `[Holesail]` in `\e[34m`, `[DEBUG]` in `\e[90m`, `[INFO]` in `\e[32m`, `[WARN]` in `\e[33m`, `[ERROR]` in `\e[31m`. DEBUG and INFO go to stdout (`console.log`), WARN to stderr (`console.warn`), ERROR to stderr (`console.error`).

The messages by source are in [server.md](server.md) and [client.md](client.md). At level 0 the server prints `Generated key pair from seed: <seed hex>` (a seed leak); at levels 0–1 the private server prints `Server listening on key: <z32(seed)>` (quirk 9).

## 8. Lookup `--lookup <key>`

`Holesail.lookup(url)`: `urlParser`; if `secure` (quirk 2!) — `argKey = z32(sha256(key))`, otherwise `z32.decode(key)` is tried, and an exception becomes `Error("Invalid key format: <key>")`. Then `HolesailClient.ping(argKey)` ([dht-records.md](dht-records.md)); `result = ping || {}`; `result.secure = isSecure` (at this point — `true` or `undefined`).

Printing to stdout (all colors in `\e[…m`, exit is always 0 — quirk 14):

```
Holesail Lookup Result 🔍          (cyan+underline+bold text, then ' 🔍' outside the color)
Host: <host | N/A>                 (label magenta, value green)
Port: <port | N/A>
Protocol: <TCP|UDP | N/A>          (protocol.toUpperCase(); for an empty object {} the protocol 'tcp' → TCP)
Private: <Yes|No>                  (secure truthy → Yes)
```

`host || 'N/A'` and `port || 'N/A'` — falsy values (0, an empty string) also give `N/A`. No record — the same four lines with `N/A` and `No` (matrix `lookup-none`; the branch "No record found for the provided key." in the code is unreachable, since the result is replaced by `{}`). An error goes to stderr: red `Error during lookup:` + a space + `<message>`, exit 0: `--lookup` without a value → `Error during lookup: seed must be 'crypto_sign_SEEDBYTES' bytes` (the value `true` turns into a key, not into a rejection); `--lookup not!valid` → `Error during lookup: Invalid key format: not!valid`. A record with invalid JSON is ignored, as if there were no record.

**Implementation.** `--lookup` without a value: the facade creates a DHT node before parsing the key and does not destroy it if the key is not 32 bytes — so the trace matches JS (matrix case `lookup-bare`, `new HyperDHT()` in the trace).

## 9. Exit codes and termination

| Code | When |
|---|---|
| 0 | help, version, `--lookup` (including with an error, quirk 14), `--key` without a value (quirk 4), no dispatcher branch matched |
| 2 | a `validateInput` error (items 3–11 of section 3, except 1–2) |
| 1 | an unhandled exception / rejected top-level promise: an invalid z32 on the client, `JSON.parse` of someone else's record in the client, `EADDRINUSE`/`EADDRNOTAVAIL` on the local `listen` of the client and filemanager (the banner is already printed), `--filemanager` without a path (`INCORRECT OR NO PATH SPECIFIED` from `livefiles`), `--__proto__ x` (quirk 12). A Node stack goes to stderr — do not compare byte by byte |
| killed by a signal | server and client modes: there are no signal handlers, `SIGINT` terminates the process by signal (the shell sees 130). No cleanup: records in the DHT stay until they expire |
| 130 | filemanager: `graceful-goodbye` catches SIGINT/SIGTERM, closes `conn` and the file server, exits with code 130 |
| 130 | live/connect with `--save-nodes`: SIGINT/SIGTERM save the table and exit (a port extension; JS shows 143 for SIGTERM, here it is 130 for both). A fatal error saves the table too and exits with code 1 |

The running modes are endless: the server holds a 50-minute `setInterval` ([dht-records.md](dht-records.md)), the client a listening socket. A `listen` error on the server is not caught (see [server.md](server.md)).

## 10. Saved DHT nodes (port extension)

Not in JS, where every node starts with an empty routing table. Off unless `--save-nodes <file>` is given; there is no default path. Live, connect and filemanager read and write the file; lookup only reads it.

- Format: text. Line 1 `holesail-nodes 1`, line 2 `saved <unix seconds>`, then one `<ipv4>:<port>` per line, freshest first.
- Reading gives an empty list (the node starts as without a file) when the file is missing or unreadable, the first line differs, the `saved` line is missing, or the file is older than the ttl (168 hours by default; a `saved` stamp in the future counts as age 0). Bad lines (hostname, IPv6, port 0 or above 65535) are skipped, repeats are dropped, at most 256 nodes are taken.
- The nodes are put into the routing table without pinging, before the node joins the network; the usual bootstrap nodes stay in the first query as well. Dead entries leave the table through the request timeout.
- Writing: the first write one interval (300 s by default) after the banner, then every interval, and once more on a signal or a fatal error. An empty table is never written, so a run without network keeps the old file. The write is atomic (`<file>.<pid>.tmp`, then `rename`); errors are ignored.
- Exit: SIGINT or SIGTERM (Ctrl+C on Windows) saves and exits with 130; a second signal during the save aborts it. `destroy` is not called, as in JS.
- Not shown in help: the help text is byte-identical to JS.
