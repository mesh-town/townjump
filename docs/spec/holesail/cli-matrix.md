# Behavior matrix of the holesail 2.4.4 CLI: arguments, output, exit code, side effect

Captured by running the real `holesail` 2.4.4 (`node src/bin/holesail.mjs`) with the network replaced: the preloader `node -r testvectors/holesail-cli/mock-dht.cjs` swaps `hyperdht` for a stub that writes calls to a trace and opens no sockets. So the "side effect" is the exact calls of the DHT layer (which arguments `createServer`, `mutablePut`, `mutableGet` received), not network activity. The random 32 bytes are replaced with `000102…1f`, so different rows share the same keys. How to read the tables:

- Only stdout is shown, with ANSI colors, the banner frame and the QR code stripped; `⏎` is a line feed; `<ts>` is an ISO timestamp; hashes are shortened to 8 characters and `…`. The exact bytes (colors, frame, QR) are in `testvectors/holesail-cli/cli-matrix.json`, field `stdout`.
- "Code": a number — the process exited on its own; "runs" — the process stayed alive (the banner is printed), on SIGINT it dies from the signal (the JS version has no handler, shell exit code 130); for the filemanager `graceful-goodbye` catches SIGINT and exits with code 130 after `dht.destroy`.
- The rows `live-fake-conn`, `conn-record-*`, `lookup-found-*`, `lookup-badjson`, `lookup-empty-obj` run with a DHT record substituted (`MOCK_RECORD`, the "condition" field).
- The network parts (real listen, real connect, data transfer) are not covered by the matrix — see the section "Not verified by running" in [README.md](README.md). The matrix is suitable for CLI parity tests: output, codes, DHT calls.
